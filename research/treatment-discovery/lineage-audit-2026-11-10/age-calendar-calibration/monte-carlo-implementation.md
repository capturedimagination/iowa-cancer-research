# Independent Monte Carlo implementation

Code and environment were pinned before the authorized stochastic runs. The first runs and same-seed reproductions are complete; [the reproduction report](monte-carlo-reproduction.md) records their counts and the calibration report-packaging failure, recovered from existing batches without new draws. This file describes implementation, not empirical validation.

The complete-tree generator in `scripts/simulate_age_calendar_trees.py` derives its breadth-first bookkeeping and immutable checkpoints from the earlier independent simulator, whose frozen SHA is `cbbdb12707fb55641bd2701a3be0c862f4f47d0b758bec7b829239cb6f084c46`. It imports neither that simulator nor the primary numerical model. The new file samples independent residual Erlang division and exponential death clocks in operational time. The same clock therefore multiplies both physical hazards. Initial types are fair; uniform-stage founders have residual shape `k-stage+1`; daughters start at stage 1 and receive independent type-transition draws conditional on their mother.

Every family is followed to physical time 4, including daughters born exactly at the endpoint. Live cell intervals are `[birth,event)`, with synthetic division/death ties assigned to death. Summing `2^-generation` across live cells computes a founder's future-blind random-forward path survival probability. Complete family survival and both sister-subtree indicators are recorded separately. A founder's first division must precede death and occur by physical time 2 to enter the pair cohort. Both sister subtrees are queried at the same physical lag, using `R(b+lag)`, not `R(b)+R(lag)`.

Birth-bin membership compares original operational event times with transformed physical bin boundaries. This avoids inverse-roundoff deciding exact bin membership. The monotone inverse preserves exact midpoint equalities; a specific nonlinear-clock fixture confirms that daughters dying exactly at a lag query are excluded. An inverse uncertainty below `1e-12` remains a numerical calculation, not an exact real-arithmetic certification.

Draw order is fixed in code: initial type, initial stage, then each stable breadth-first frontier's division durations, death durations, and interleaved daughter-type uniforms. Zero-death cases consume no death draws. The two-type kernel consumes a uniform for every daughter even at perfect transmission. Resource guards fail explicitly before allocation; trees are never replaced or silently truncated. Per-founder synthetic checkpoints use fixed batches of 250. Resume checks code, protocol, environment, RNG state and checkpoint identities. Aggregates retain all planned rows, zero selected counts, empty birth bins, and zero removed-cohort contribution counts. No selected-count Gaussian precision rule is used in this new protocol.

The calibration generator in `scripts/simulate_shared_calibration.py` consumes only saved, independently checked `p,j` and estimator moment records. It requires the comparison report to have status `PASS`, all 20 cases, no failures, the frozen field count, and matching protocol and primary-input hashes. Root authorization remains separate from this automatic evidence check.

Each calibration setting comprises 50,000 independent whole experiments in batches of 5,000. It first draws a calibration count `X~Binomial(m,p)`, then target-pair counts in the fixed category order `00,01,10,11`. One fit `X/m` is shared by all `n` pairs within that experiment. Four categories preserve the two target sample means required for unbiased sample covariance. The four scores and their observed mean squared deviations about the supplied analytic means are accumulated without storing giant individual-pair arrays. All 720 settings have distinct frozen seed tuples.

The 5,760 calibration checks use the frozen Bernstein bounds and known analytic variances, with a range-based variance upper bound for squared deviations. These describe repeated synthetic experiments. They are not confidence intervals for one cancer dataset. Probability adjustments for numerical sampling are explicitly recorded and limited to `1e-8`; the stated concentration laws condition on the intended exact model probabilities. Floating-point integration and the declared numerical slack are not certified interval arithmetic.

Pre-run fixtures cover hand-constructed trees and count tables, exact boundaries, residual stages, draw order, no-overwrite checkpoints, all four score ranges on small exhaustive supports, undefined denominators, and rejection of unverified gate evidence. The pinned fixture reports and source/environment hashes are in [tree run freeze](tree-monte-carlo/run-freeze.json) and [calibration run freeze](calibration-monte-carlo/run-freeze.json). Earlier study flags and low-count unresolved checks remain unchanged.
